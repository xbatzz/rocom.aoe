# 游戏原生 UI 素材需求清单

审查日期：2026-09-11。面向下一轮素材筛选，本轮只产出文档。

## 结论与取舍

当前网站已经有足够的游戏内容图片。最值得补的是 **主按钮底板、六维数值图标、精灵选中框**，其次才是少量导航图标、标签底板和游戏语义标记。保留网页的布局、文字、表单和数据可视化，让原生素材集中出现在行动入口、当前选择和精灵身份上。

本清单共 **P0 3 组、P1 8 组、P2 2 组**。P0 + P1 为 11 组；按每组建议数量计算，约 22 个独立图形，不含可选状态版本。成套图标按实际语义拆分计数，没有把整套游戏界面隐藏在一个需求里。第一轮只搜文末的 10 项，不需要把所有目录导入项目。

- **P0：明显改善网站风格，必须找。** 必须优先搜索，不代表找到不合适的素材也要使用。
- **P1：找到合适的会明显更好。** 若缩小后不清楚、语义不确定或无法适配，保留现状。
- **P2：纯装饰，可有可无。** 不占用第一轮搜图时间。
- 下文的需求名称是搜图描述，**不是游戏资产文件名**。所有推荐目录只表示检索顺序，未验证其中一定存在相应素材。

## P0 / P1 素材需求

尺寸均指网页上的建议显示尺寸，原图优先保留约 2 倍尺寸以适应高清屏。可拉伸底板需确认中部能平铺 / 拉伸、边角不会变形；没有这些条件就继续使用 CSS。通用底板不要带烘焙文字、数字、宠物或操作图标。

### R01 · 主行动按钮底板 — P0

- **使用页面和具体位置：**首页英雄区“开始对战分析”（`adventure-button`）；通过小范围试用后，可复用到配队中的主要生成操作。次级链接和管理操作不套用。
- **素材类型 / 数量：**按钮底板，1 个主体；有匹配的按下态可顺带保存，不强求完整状态组。
- **视觉特征：**优先暖金 / 蜂蜜色圆角底板，细亮边、轻微凸起或柔和内描边，中心平整，适配现有纸张与蓝灰手册色。避免厚重金属、强光晕和带固定文字的按钮。蓝绿色版本仅作为同等清晰度下的备选，不两套并用。
- **优先搜索目录：**`CommonStatic` → `PetUIStatic` → `Atlas/PetUI`。
- **建议尺寸 / 比例：**显示高 44–48 px，宽约 140–190 px；横向约 3:1–4:1，可横向或九宫格拉伸；左右留出文字与箭头空间。
- **保留网页实现 / 放弃条件：**文字、链接语义、`ArrowRight`、焦点环、禁用状态继续使用网页原生实现。若只有一张带字完整按钮，或缩放后边角粗大，继续使用现有 CSS 底板。

### R02 · 精灵六维数值图标 — P0

- **使用页面和具体位置：**宠物详情“战斗资料”的六维数值行；配队构筑的数值区与速度线；对战“属性”页签的“实战属性对比”；图鉴卡片的生命、速度、最高单项摘要。
- **素材类型 / 数量：**数值语义图标，共 6 个：生命、物攻、魔攻、物防、魔防、速度。总种族值不另外找图标。
- **视觉特征：**透明底、清楚的剪影、边缘干净、同一套线条粗细；生命可呈生命徽记，物理与魔法攻击 / 防御应能互相区分，速度具有方向感。形状描述仅帮助找图，具体含义必须核对，不能把一个普通“攻击”图标硬映射成两种攻击。
- **优先搜索目录：**`CommonStatic` → `Atlas/GameInfo` → `PetUIStatic`。
- **建议尺寸 / 比例：**近方形；数据行 18–24 px，紧凑摘要 14–16 px；原图建议至少 48 × 48 px，优先在 20 px 预览下挑选。
- **保留网页实现 / 放弃条件：**名称、数值、百分比、数值条、雷达图和比较色继续使用网页原生实现。不要混淆这里的六维数值与 `Species.png` 的战斗属性；语义不确定的单项保留文字。

### R03 · 当前精灵选中框 — P0

- **使用页面和具体位置：**配队当前槽位；对战“双方对位”上方当前我方精灵的队伍入口；宠物详情进化链中的当前精灵节点。首页六槽为后续同风格复用位置，但当前没有独立的槽位选择状态，不能给它伪造选中态。
- **素材类型 / 数量：**选中态框，1 个；优先只覆盖头像，避免为宽窄不同的整张信息卡搜多套框。
- **视觉特征：**透明中心、金色或低饱和青金色细轮廓，四角略有收边 / 刻角，缩小仍清楚。避免大面积发光、夸张翅膀、稀有度宝石、会盖住头像的装饰。
- **优先搜索目录：**`Raw/PetTeam` → `CommonStatic` → `Raw/PetBag`。
- **建议尺寸 / 比例：**1:1；适配 48–80 px 头像，原图建议 128 × 128 px 以上。若要扩展到整卡，必须可九宫格拉伸，否则只用于头像。
- **保留网页实现 / 放弃条件：**普通头像底色、空槽加号、卡片边框、拖动目标反馈和键盘焦点继续使用网页原生实现。不能让选中框同时代表“已收集”“首领”或稀有度。

### R04 · 四个核心功能的导航图标 — P1

- **使用页面和具体位置：**Sidebar 桌面和移动菜单的“图鉴 / 配队 / 技能 / 对战”一级导航；之后可在相同功能的页标题旁复用。当前“首页”和“配队”共用 `Gamepad2`，其中配队更值得获得独立语义。
- **素材类型 / 数量：**小型功能图标，最多 4 个，不搜索全站每个导航项的皮肤。
- **视觉特征：**图鉴偏册页 / 档案，配队偏多精灵 / 阵容，技能偏技能符号 / 能量，对战偏交锋；透明底、简明轮廓、少量平涂色。同组应具有一致大小和笔触，能与保留的 Lucide 图标共处。
- **优先搜索目录：**`Atlas/GameBtnIcon` → `PetUIStatic` → `CommonStatic`。
- **建议尺寸 / 比例：**显示 18–22 px；近方形，原图建议 48–64 px；光学重量接近现有约 18 px 导航图标。
- **保留网页实现 / 放弃条件：**导航文字、当前页底板、右侧星标、首页及低频工具图标继续使用网页原生实现。若候选只有细节丰富的大入口插画，或四个图标风格差异过大，整组继续用 Lucide，不强行凑齐。

### R05 · 标签导航的选中底板 — P1

- **使用页面和具体位置：**宠物详情“概览 / 战斗资料 / 自有技能 / 学习技能”；配队配置面板“选择精灵 / 构筑配置”；对战五个任务标签；培育工具的三个模式入口。
- **素材类型 / 数量：**标签底板，1 个通用选中版本。不是为每个栏目找独立图片。
- **视觉特征：**浅金或蓝绿色的小页签，细亮边或轻微纸页压边；轮廓简单，中心无纹样、无文字。要能适配横向排列，也能适配手机上较窄、较高的标签。
- **优先搜索目录：**`CommonStatic` → `Atlas/PetUI` → `PetUIStatic`。
- **建议尺寸 / 比例：**常规高 32–44 px、宽约 70–150 px；移动对战标签可能高约 48–56 px。优先能双向九宫格拉伸的版本；不能满足不同高度时，只用于宠物详情，其余沿用 CSS。
- **保留网页实现 / 放弃条件：**未选中底色、文字、图标、布局、键盘切换和选中语义继续使用网页原生实现。Sidebar 的金色当前页底板已经足够，不另搜同类素材。

### R06 · 首领身份徽记 — P1

- **使用页面和具体位置：**图鉴卡头像 / 名称附近已有的“首领”标签；宠物详情顶部“首领形态”和进化链首领阶段；配队精灵的 `Crown` + “首领”。
- **素材类型 / 数量：**状态图标，1 个。
- **视觉特征：**小型金色冠形、徽记或其他经确认代表首领的游戏符号，透明底、剪影清楚；适合作为标题旁标记，不占用整条标签宽度。
- **优先搜索目录：**`CommonStatic` → `PetUIStatic` → `Atlas/PetUI`。
- **建议尺寸 / 比例：**近方形，行内 14–18 px，头像角标不超过 24 px；原图建议至少 48 × 48 px。
- **保留网页实现 / 放弃条件：**“首领”文字及显示条件继续使用网页原生实现。“可转首领”不能直接使用已是首领的徽记而删去说明；异色、炫彩、污染和奖牌图标均不能替代它。无法确认含义时继续使用现有文字 / `Crown`。

### R07 · 少量重点面板的细边框 — P1

- **使用页面和具体位置：**首页英雄区 `adventure-cover` 外轮廓；通过首页试用后，最多再扩展到配队“阵容分析”或对战“主结果”这一层重点区域。不是每个 `Card` 都替换。
- **素材类型 / 数量：**面板边框，1 套可拉伸边角。
- **视觉特征：**研究手册 / 轻魔法书感的细边，奶油色或低饱和金线、轻微压边、小尺寸角花；中心透明，文字区域干净。若候选是羊皮纸风，优先平整细腻纸边，排除破损焦边、厚木框和满屏卷轴。
- **优先搜索目录：**`PetReport/PetReportStatic` → `Atlas/PetUI` → `PetUIStatic`。
- **建议尺寸 / 比例：**必须可九宫格拉伸或拆分角 / 边；适配约 320–1100 px 宽、内容决定高度的面板。显示边宽建议 2–6 px、角部装饰约 12–24 px，不能挤占移动端内容。
- **保留网页实现 / 放弃条件：**面板底色、正文、圆角布局、留白和阴影继续使用网页原生实现。若候选只是普通圆角细线，CSS 已足够；若只能整张拉伸、中心不透明或夜间主题过亮，也不采用。

### R08 · 进化链连接箭头 — P1

## 挑候选时的最低要求

1. 每项先留 1 个最合适候选；确实难分时最多留 2 个。记录真实目录、真实文件名和预览图，之后再决定导入，避免整图集搬入项目。
2. 图标需有透明背景；图集候选要能识别独立裁切边界。保留原始尺寸、透明通道和必要留白，避免边缘混入邻近单元格。
3. 按最终显示尺寸查看，并分别放在奶油纸色和蓝灰暗色底上。20 px 下认不出的图标、暗底发脏或亮底消失的轮廓，不进入候选。
4. 底板优先无字、无数字、无固定角色；边角固定、中部可伸缩。现有 CSS 可以表达的普通圆角 / 细线，不值得单独导入图片。
5. 一屏只让主 CTA、当前选择、少量身份标记成为视觉重点。R03 不与厚头像框叠加，R07 不铺到所有卡片，R12 / R13 不为填空而添加。
